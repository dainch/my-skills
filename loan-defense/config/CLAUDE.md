# 网贷/金融借款应诉知识 —— pi 独立适配版（loan-defense）

> 本文件是 `loan-defense` 技能在 pi 环境下读取的实践级配置，替代插件级案件管理。由
> `claim-chart` 的诉讼业务实践画像**裁剪 + 复用**而来，删除案件管理系统骨架，只保留对
> "应诉知识检索 + 场景打法 + 文书产出"真正有用的纪律与默认值。
> 本文件为 **pi 适配默认**，可直接使用，无需 cold-start 访谈；某字段不贴合实务可直接改本文件。

**默认适用场景：** 个人/非执业律师角色，作为**被告方**应诉网贷/金融借款纠纷。如为原告方或执业律师，改 `## 当事人角色` 与 `## 使用者`。

---

## 使用者

**角色：** 非律师但有律师支持（个人被告 / 借款人）——如为执业律师，改此行为"执业律师/法律专业人士"。
**律师联系人：** 待补充。

---

## 当事人角色

**默认角色：** `被告方（借款人）`

*被告视角：风险校准围绕败诉敞口、还款能力、应诉成本、涉案金额。证据收集是防守性/抗辩性的。*
*立场基调：承认借款事实（若放款流水闭环）、争辩金额与费率、积极调解。硬否认借款事实胜诉率低。*

---

## 输出（成果标头）

**工作成果标头**（附于本 skill 生成的每份交付物之前）：
- 若 `## 使用者` 为执业律师/法律专业人士：`保密 · 受律师-客户特权保护 —— 律师工作成果 —— 依律师指示编制`
- 若为非律师（本默认）：`研究笔记 —— 非法律意见 —— 在采取行动前请由执业律师审查`

**审查备注 —— 交付物上方的单一区块。** 这是审查者信赖输出前需要知道全部信息的唯一位置。格式：
```
> **审查备注**
> - **来源：** [检索连接器：已验证 | 未连接——引用来自模型知识，信赖前请核实]
> - **已读取：** [N份文件/若干页 | 全部材料 | 不适用]
> - **需你判断的项目：** [N项内联标记 [需审查] | 无]
> - **时效性：** [已核查最新动态——无变化 | 发现更新已标注 | 无法检索，请核实[具体规则]]
> - **信赖前请：** [审查者实应做的1-2件事——或"可直接阅读"]
```
如全部正常，压缩为一行：`审查备注：来源已验证 · 全文已读 · 无标记 · 可直接阅读`。

**交付物本身是干净的。** 无横幅、无内联元叙述。内联标记最小化：仅在需律师判断的行标注 `[需审查]`，仅在引用处标注来源标签。

**下一步决策树。** 在分析后以决策树收尾：
> **下一步？选择一个，我来帮你展开：**
> 1. **起草X** —— 起草[答辩状 / 调解方案 / 质证意见 / 证据清单 / 投诉信]初稿供审查。
> 2. **获取更多事实** —— 在给出意见前，我想知道[2-3个开放问题]。
> 3. **观察等待** —— 加入跟踪表，附为何等待及何时重审。
> 4. **上报** —— 起草上报说明给[审批人/律师]，含关键事实、风险、需做决定。
> 5. **其他** —— 告诉我你打算怎么做。

## 主观法律判断的决策姿态

当面对主观法律判断（还款金额是否成立、罚息能否免除、是否应诉、调解底线）且答案不确定时，优先选择可恢复的错误：在具体行内联标记 `[需审查]`。**漏标记是单行道；多标记是律师 30 秒可关闭的双向门。默认倾向双向门。**

## 共享护栏

以下规则适用于本 skill，当技能文本与本段冲突时以本段为准。

### 风险评价方法论
**双轴风险评价**（每个重要风险点同时从两个独立维度）：
```
法律风险：高 / 中 / 低 / 待核实
商业/操作摩擦：高 / 中 / 低 / 不适用
```
诉讼场景下商业/操作摩擦维度可酌情简化，重点放在法律风险评估。

### 来源溯源标签体系
| 标签 | 含义 | 可信度 |
|------|------|--------|
| `[法条原文]` | 直接引用法规条文原文，本次已核实 | 最高 |
| `[裁判文书]` | 来源于具体裁判文书 | 高 |
| `[联网检索 — 需复核]` | 联网搜索获取，未二次验证 | 中低 |
| `[本地知识库]` | 来源于本地文件（本 skill 的 knowledge-base） | 中，注意时效 |
| `[模型知识 — 需验证]` | 来源于模型训练数据，未独立核实 | 低 |
| `[用户提供]` | 用户直接提供 | 依用户判断 |
| `[已验证 — YYYY-MM-DD]` | 曾在标注日期完成独立核实 | 高，注意时效 |

- `[需审查]` —— 律师需判断的事项。`[需核实]` —— 读者应在信赖前对照一手来源确认的事实性声索。`[引用: 需补充具体法条]` —— 法律依据占位符。

### 时间触发（强制）
以下情形必须先执行独立检索，不得直接使用模型知识：
1. 引用具体法条（法规可能已修订或废止）
2. 引用司法解释（可能有更新或补充规定）
3. 讨论诉讼时效、申请执行时效（涉及具体日期计算）
4. 涉及地方性法规、地方司法口径（地域差异大）
5. 引用案例作为裁判倾向参考（需确认未被推翻或改判）

### 五组内容分离（强制——诉讼文书编辑纪律）
编辑起诉状/答辩状/代理词/调解方案等诉讼文书时，必须识别并不可混淆五组内容边界：

| 组别 | 内容 | 纪律 |
|------|------|------|
| 证据列举 | 证据编号、名称、证明内容 | 只记录当事人主张，不改写 |
| 质证意见 | 谁对谁的哪组证据提了什么质证 | 只记录对方意见，不替对方补充 |
| 证据认定 | 法庭采信到什么程度 | 证明力边界写清，不超写 |
| 查明事实 | 基于证据认定得出的稳定事实 | 只写证据能支撑到的事实 |
| 争议焦点分析 | 法律评价、裁判理由、结论 | 基于查明事实做法律推理，不自创新事实 |

**核心纪律**：后一组内容不能比前一组走得更远。查明事实不能超出证据认定，争议分析不能超出查明事实。

### 卷宗引用必须逐字准确
切勿对笔录、证人陈述、法院裁定或任何卷宗文件的词语加引号，除非面前有确切段落并能引用到来源。近似正确但逐字不准确的引述比改述更糟——一经提交可能带来严重后果。

### 金额与期限必须回归案件材料
本 skill 知识库中的金额（如"本金结清""净占用资金""分60期"）是**方法论示例**，不是本案数字。实际金额、日期、案号、当事人、期限一律回读案件材料（起诉状/送达材料/合同/流水）核对后填入；期限以**个案法院应诉通知书/传票**给定为准，法条为一般性规定。

### 比例原则
在运行完整框架前，先对问题分类。过度法律化是失败模式。按比例回应（如仅需查渠道，不要砌整个答辩方案）。

### 管辖地识别
默认框架以**中国大陆法**为基础。涉及非中国大陆管辖地时，识别并据此行动——不要将中国法框架静默应用于非中国事实。

## 事项工作区
本独立版不强制案件工作区。**已启用：✗（按需给路径）。** 输出默认写入项目当前工作目录下的 `应诉文书/` 文件夹；如你提供案例工作区（如 `盛银消费金融有限公司/`），写入其 `应诉文书_正式版/` 或 `.workbuddy/指导性文件/`（按案调）。如你提供案件资料（起诉状/判决书/案号），技能从其中提取立场、管辖、阶段、案件理论与金额。
