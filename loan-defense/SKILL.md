# /loan-defense

1. 加载技能目录下的相对路径 `config/CLAUDE.md` → 角色、工作成果标头、决策姿态、共享护栏、文件存储。若该文件缺失或含 `[PLACEHOLDER]`，回退内置默认并继续（不阻断）：成果标头（非律师）＝"研究笔记 —— 非法律意见 —— 在采取行动前请由执业律师审查"；决策姿态默认"双向门（多标记缺口）"。
2. **定位场景**（从用户描述、`--scenario` 或 `--deliverable` 判断；无法判断则向用户列 2–3 个选项并说明利弊，给出推荐默认——不要抛开放式长问题）。场景清单见第 4 步。
3. 加载技能目录下的相对路径 `references/knowledge-base.md`（应诉知识主体，含场景手册、法律依据、证据清单、通用抗辩武器库、风险红线、修正与待核实清单）。本 skill 作为独立技能运行，不依赖插件级案件工作区；如你本地有案例工作区（如 `盛银消费金融有限公司/`）或 `matter.md`（立场、管辖、阶段、案件理论），提供路径供加载以对齐数字。
4. **场景清单**（对应 `references/knowledge-base.md` 第三节）：
   - `催收` → 场景A 暴力/违规催收
   - `冻结` → 场景B 微信/支付宝/银行卡冻结（财保 vs 执保）
   - `支付令` → 场景C 法院支付令
   - `退费` → 场景D 信用卡不合理费用
   - `代偿` → 场景E 征信代偿
   - `仲裁` → 场景F 网贷仲裁（先予/网络/虚假）
   - `平台起诉` → 场景G 网贷平台起诉
   - `债权转让` → 场景H 债权转让后起诉
   - `短信` → 场景I 1068 骚扰短信
   - `发票` → 场景J 利息发票/进项税
5. **取物料**：按场景从知识库取出"判断信号 / 应诉步骤 / 法律依据 / 话术或文书 / 注意事项"，并取"证据 checklist""通用抗辩武器库""风险红线"。
6. **校验法条（强制）**：引用具体法条、司法解释、诉讼时效/申请执行时效、地方司法口径，或引用案例作裁判倾向前，**必须先独立检索核对**（法规可能已修订废止），不得直接用模型知识。引用处打来源标签（见 config/CLAUDE.md 来源溯源）。
7. **产出交付物**（按 `--deliverable` 或用户要求）：答辩状 / 调解方案（含调解书保护条款）/ 质证意见 / 证据清单 / 投诉信。撰写诉讼文书时执行**五组内容分离**与"查明事实不超证据认定、争议分析不超查明事实"纪律；金额/日期/主体一律回到案件材料核对，不默认知识库通用数字。
8. **输出标头**：每个交付物附成果标头（非律师时"研究笔记 —— 非法律意见 —— 在采取行动前请由执业律师审查"），并在交付物上方附"审查备注"区块（来源 / 已读取 / 需判断项 / 时效性 / 信赖前请）。
9. **存储**：有活跃案件 → 写入该案件的 `应诉文书_正式版/` 或 `.workbuddy/指导性文件/`（按案调）; 无案件 → 写入当前工作区 `应诉文书/` 或知识区。追加一行至该案 `memory/` 日志。
10. **返回摘要**：定位的场景、采取的策略、引用的法条（含来源标签）、交付物路径、需执业律师判断的 `[需审查]` 项、时效性提示。
11. 每个主观法律判断（胜算、风险等级、是否应诉），标注 `[需审查]`；漏标是单向门，多标是律师 30 秒可关的双向门——**默认倾向双向门**。

## 本 skill 不做什么

- **不下结论**：不认定是否应还、金额是否成立、胜诉概率——只给策略与物料，标 `[需审查]`。
- **不替代执业律师**：涉及起诉、答辩、和解、签署、处分权利，交由律师复核并作最终决定。
- **不编造数字**：所有金额/日期/主体回归案件材料；知识库通用数字仅作方法论示例。
- **不套用不适用法条**：如信用卡专用条款（信贷70条）不当然适用消费贷，须区分。
