# 发布前硬门禁

以下任一项不满足时，必须停止并说明缺口；不得包装成已完成。

## 1. 事实与来源

- 关键事实没有来源，不能写成确定结论。
- 涉及法规、规范、政策、产品功能、价格、时间节点等易变信息时，必须核实来源或明确“待核实”。
- 引用用户素材时，不把截图、个案、经验外推为通用规则。

## 2. 推荐运营规范 / 不良信息

- 标题、封面标题、摘要、首屏导语不得使用夸张标题，且内容不得与标题严重不符。
- 涉及时事、公共政策、社会事件、事故灾害时，必须标注来源与时间；旧闻旧事必须明确写出发生时间、地点。
- 不得蹭炒社会热点、消费灾难事故、放大冲突焦虑、制造“马上出事/马上封号”式惊悚表达。
- 不得使用“防失联先关注”“后面有大料”“先转发再看”之类诱导关注、故留悬念或诱导互动的写法。
- 不得发布不完整内容，再通过二维码、文字、链接、图标等方式引导用户跳转到其他内容、小程序、公众号/服务号、视频号、第三方网页或 App。
- 不得在账号简介、正文、评论区、公众号消息中嵌入外部链接、二维码、回复关键词、私信领取等离页导流信息。
- 可保留“欢迎投稿与交流”这类中性栏目标题；其下固定展示“投稿邮箱”“小编微信”不视为发布门禁问题。仍不得写“扫码领取”“回复领取”“私信领取”“加微信看全文”等导流动作。
- 不得通过多重跳转、定向引流、先关注再获取等方式，最终引导用户去站外或线下交易。
- AI 生成图片、演绎画面、非实拍示意如可能被误读为真实现场，必须显式标注“示意 / 演绎 / AI 生成”。
- 未核实专业资质或权威来源前，不写医疗、金融、法律、政策类确定性建议。

## 3. 敏感信息

- 项目名称、参建单位、人员姓名、坐标、合同、原始监测数据未脱敏时，不得进入公开成稿。
- 现场照片或图纸可能泄露位置、编号、单位信息时，先提醒处理。

## 4. 封面与图片

- 公众号主封面未生成图片文件时，不得声明“封面已完成”。
- 主封面未验证尺寸和宽高比时，不得声明可直接使用；默认合格值为 `2350 × 1000`、`2.35:1`。
- 直接使用外部图片、音乐、视频素材时，必须提醒版权或授权风险。

## 5. Output 文件规范

- 新建 `600-Output/` Markdown 必须包含 `output_profile` 与 `source_refs`。
- `source_refs` 不得为空，且不得直接指向 `100-Raw/` 或外部 URL。
- Output 可以使用 `status` 表达 `draft` / `reviewing` / `ready` / `published` 等产出流程进度。
- Output 不得使用 `type`、`categories`、`sources` 等 Wiki 字段，也不得把 `summarized` / `compiled` / `stale` / `conflicted` / `archived` 等 Wiki 生命周期值写入 `status`。

## 6. 成品完成度

- 用户没有要求草稿时，不交付只有提纲、占位符或内部工作备注的版本。
- 公众号正文默认应自洽完整，不交付“正文只放一半，剩余内容靠跳转/私信/扫码领取”的版本。
- 视频成片不能只是静态单画面；至少要有节奏推进、字幕/旁白或明确的可录制脚本。

## 7. 工程项目公开边界

- 未经用户确认，不公开具体项目名称、线路区间、站点、坐标、结构标高、净距、监测原始数据、合同金额、报价文件、审查意见和未盖章报告。
- 对“已完成项目、合作单位、获奖、专利、论文、项目数量”等公司业绩表述，必须来自公开画册或用户确认材料；不能为了增强传播力自行扩写。
- 正在投标、报价、审查、报地铁、报业主、未定稿、内部比选、校审意见回复等材料默认视为非公开素材。
- 公开案例可优先做脱敏表达：用“某城市轨道项目”“某市政管廊项目”“某运营地铁区间邻近工程”替代全称。
