# 工程评审汇报 PPT 生产线

面向专家评审/建设方汇报场景的工程类 PPT 生产流程。目标五要素：**专业、严谨、数据可溯源、可编辑、制作可复现**。

## 适用边界

- 适用：桥梁/栈桥/隧道等土木工程类评审汇报、面向专家或建设方的正式汇报。
- 不适用：营销 PPT、产品白皮书、非工程类汇报、纯数据大屏（超出本 skill 范围，如实告知用户另行处理）。

## 工作区约定

- 项目根目录：本次汇报所属工程项目的根目录（下文所有相对路径以此为准，如 `build/`、`preview/`）。
- 一切中间产物留在项目内：`build/` 放生成脚本与素材，`preview/` 放每页预览图，最终 PPTX 放项目根。
- 保留生成源文件（build_ppt.py 等），做到"改参数即可重出整稿"。

## 三条不可违反的硬规则

1. **数据唯一源**：设计参数、型号、数量、高程、坐标只能取自设计图纸原件；施组/方案等参考文件仅用于印证工艺术语与实景图，严禁混入其工程数据。发现图纸自相矛盾（如高程基准不一致）时如实列入"提请评审事项"，不得自行择一。
2. **成果为纲**：成功标准 = 打开后每页观众一眼看懂、字能看清、数据与图纸一致。渲染成功/校验通过只是过程指标，不等于完成。
3. **图片 > 表格 > 短句**：能配图不用表格，能用表格不用文字；每页 1 个主视觉 + ≤1 段要点（3–5 条），禁止整页文字。

## 生产流程（五阶段）

### 阶段 0 · 确认输入
开工前确认：① 设计图纸原件（数据唯一源）；② 参考素材（实景图/工艺术语）；③ 页数与章节裁剪（默认 18 页骨架，见 references/outline-template.md）；④ 交付格式（默认 .pptx 原生可编辑）。用户未明确且非整体委托时先问，不得代选；用户整体委托（"都你来定"）时自选并在交付说明列出假设。

### 阶段 1 · 取材与素材库
- 从图纸 PDF 裁剪节点大样/布置图（参照既有 build/crop_assets.py 模式）。
- 从参考 docx/ppt 提取实景照片建素材库（build/media/），全部配图须来自工程资料，禁用网络图片。
- 数据提取后做独立核对清单（逐图核验），核对记录随交付物存档。

### 阶段 2 · 大纲与配色定调
- 按 references/outline-template.md 的章节骨架填内容，先给用户审大纲再生成。
- 配色遵循 references/production-standard.md §3.1 的 60-30-10 流程；默认"工程蓝"体系（主色蓝系 + 中性色 + 橙仅用于风险警示，≤3 色相）。
- 字体统一思源黑体体系（标题 Bold / 正文 Regular），交付必须嵌入字体或附 .otf（见 references/cjk-pitfalls.md）。

### 阶段 3 · 生成（路线选择）
默认 **路线 A · 原生 PPTX（python-pptx）**——产物全元素可编辑、保留可复现脚本：
- 用工作区捆绑 Python + python-pptx；配色/字体走主题层（自定义主题颜色、自定义字体），组件层沉淀 panel/kpi/table/pic_round/risk 等组件函数，禁止在 run 上写死色值或单独设字体。
- 能模板化的一律模板化：主题层 → 版式层（Slide Layout）→ 组件层（build.py 函数）。
若用户提供既有 PPT 模板要求套版，走 **路线 B · 模板克隆**：先用 python-pptx 解析模板的版式、配色、组件与字体，建立版式清单，再把内容映射进克隆骨架；保留模板母版不动，只填充内容。
若用户明确要网页风精排演示且不要求可编辑源文件：本 skill 不支持该形态，如实说明并与用户确认后再决定是否仍按原生 PPTX 路线出稿。

### 阶段 4 · 质检循环（不过不许交付）
1. `python build/lint_ppt.py`：版式自检（文字溢出/越界/重叠/安全区），出问题改 build 脚本重出，不在 PowerPoint 里手改。
2. OpenXML 校验：环境装有 officecli 时执行 `officecli validate`，要求 0 错误（图表轴 ID 等损坏坑见 references/cjk-pitfalls.md）；未安装则跳过本步，并在交付说明中注明『OpenXML 校验未执行』。
3. `build/render_preview.ps1` 逐页导出 PNG，逐页目检 + 视觉复查；发现溢出/重叠/对齐/风格不一致 → 回阶段 3 修正，重新检查。
4. 数据核对清单逐项打勾。

### 交付
交付说明必须包含：生成的文件清单、检查与修改记录（哪页改了什么）、遗留风险（图纸疑点、未验证项）。

## 依赖说明（自包含）

- 不依赖任何其他 skill，可单独分享；全部规则在 SKILL.md 与 references/ 内。
- 必需工具：Python 3 + python-pptx + Pillow（生成与图片处理）。
- 可选工具（缺失时降级而非报错）：officecli（OpenXML 校验）、Windows + PowerPoint COM（render_preview.ps1 逐页预览）、PDF 渲染工具（裁剪图纸素材）。
- 项目既有 build/ 脚本仅作起步模板，缺失时按本 skill 规则从头编写即可。
